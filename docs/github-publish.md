## 第一阶段：发布前的隐私清理（最重要）

> ⚠️ **这一步千万不能跳过。**
> 一旦把真实账号密码推到公开仓库，即使立刻删除，
> 也可能已被搜索引擎和爬虫抓取，**无法挽回**。

### 1.1 运行隐私自检工具

**双击 `check-privacy.bat`**

它会自动检查：
- 有没有生成过含真实账号的 `config\config.json`
- 有没有残留运行日志 `data\` 目录
- 有没有出现手机号、内网 IP、学号格式的数字串

**看到「自检通过」才继续下一步。**

如果提示有问题，按它的提示删除对应文件即可。

### 1.2 手动二次确认（重要）

自动扫描只能发现常见格式，**请再手动查一遍**：

1. 用记事本打开 `config\config.example.json`
2. 确认里面的内容是**中文占位符**，例如：
   - `"base_url": "这里填你的门户地址"`
   - `"username": "这里填你的学号"`
   - `"password": "这里填你的密码"`
3. **如果发现真实信息，立刻改回占位符**

### 1.3 确认没有 config.json

看 `config\` 文件夹里：

| 文件 | 该不该有 |
|---|---|
| `config.example.json` | ✅ **必须有**（这是模板） |
| `config.json` | ❌ **不能有**（这是你的真实账号密码） |

**如果看到了 `config.json`：**

- **不要删它**（你自己还要用）
- 但**绝对不能上传**
- 本项目的 `.gitignore` 已经帮你屏蔽了它

### 1.4 确认没有 data 目录

`data\` 里是运行日志和缓存，**不应该上传**。

如果存在，双击 `uninstall.bat` 停掉程序后删除它即可（程序下次运行会自动重建）。

### 1.5 最终检查清单

逐项打勾，**全部确认后才进入下一阶段**：

- [ ] `check-privacy.bat` 显示「自检通过」
- [ ] `config\config.example.json` 里全是中文占位符
- [ ] `config\` 里**没有** `config.json`
- [ ] 项目里**没有** `data\` 目录
- [ ] 用记事本搜索过自己的学号，确认搜不到
- [ ] 用记事本搜索过自己的密码，确认搜不到

## 第二阶段：注册 GitHub 账号

> ✅ **已有账号的同学可以跳过这一阶段**，直接看第三阶段。

### 2.1 打开注册页面

用浏览器访问：**https://github.com/signup**

（中文界面可在页面底部切换语言为「简体中文」）

### 2.2 按提示填写

| 步骤 | 填什么 | 注意事项 |

| ① 输入邮箱 | 你的常用邮箱 | 后面要收验证码，别填错 |

| ③ 输入用户名 | 自己起一个 | **只能用字母、数字、短横线**，会出现在你的主页地址里 |

**用户名建议：**

访问 **https://github.com**，右上角能看到你的头像就成功了。

> 🔐 **重要提醒**：

## 第三阶段：创建新仓库

### 3.1 进入新建页面

在 GitHub 页面右上角，点击 **`+`** 号，然后选择 **`New repository`（新建仓库）**。

或者直接访问：**https://github.com/new**

### 3.2 填写仓库信息

| 填写项 | 填什么 | 说明 |
|---|---|---|
| **Repository name**（仓库名称） | `campus-autologin` | **必填**，只能用字母、数字、短横线、下划线 |
| **Description**（描述） | `校园网 Portal 自动登录工具，零依赖、开箱即用` | 选填，但**建议填**，会显示在仓库标题下面 |
| **Public / Private**（公开/私有） | 选 **Public（公开）** | 公开才叫开源；选私有则只有你能看 |
| **Add a README file** | ⚠️ **不要勾选** | 本项目已经有 README，勾了会冲突 |
| **Add .gitignore** | ⚠️ 选 **None（无）** | 本项目已经准备好 `.gitignore` 文件 |
| **Choose a license** | ⚠️ 选 **None（无）** | 本项目已经准备好 `LICENSE` 文件 |

> **新手最容易踩的坑**：
> 如果勾了「Add a README file」或选了协议，
> 后面上传自己的同名文件时会报错「文件已存在」。
> **这三个选项都不要勾、不要选。**

### 3.3 点击创建

点页面最下方的绿色按钮 **`Create repository`（创建仓库）**。

创建后会看到一个空仓库页面，上面有英文的初始化提示——**不用管它**，
直接看下面的第四阶段。

### 3.4 仓库命名规范（避坑提示）

| 建议 | 原因 |
|---|---|
| 用短横线分隔单词：`campus-autologin` | 比下划线更常见、更好读 |
| 全部小写 | 避免大小写混淆 |
| 不要用中文 | 虽然支持，但分享链接容易乱码 |
| 不要用空格 | 空格会被自动替换成短横线 |

## 第四阶段：网页端上传文件

网页端上传**不需要安装任何软件**，适合一次性上传整个项目。

### 4.1 先确认要上传的内容

上传前，确认项目文件夹里包含这些（**不能漏**）：

```
campus-autologin/
├── setup.bat
├── install.bat
├── uninstall.bat
├── status.bat
├── README.md
├── LICENSE
├── .gitignore
├── config/     ← 整个文件夹（含 config.example.json）
├── lib/        ← 整个文件夹（6 个文件，程序的全部代码）
├── docs/       ← 整个文件夹（2 个说明文档）
└── tests/      ← 整个文件夹（4 个测试文件）
```

**同时确认这些不在里面：**

- ❌ 没有 `config\config.json`
- ❌ 没有 `data\` 文件夹

> **特别提醒**：`.gitignore` 这个文件名以点开头，
> 在 Windows 资源管理器里默认可能看不到。
> 需要先打开「查看」→ 勾选「文件扩展名」和「隐藏的项目」。

### 4.2 进入上传页面

在你的仓库页面，点击 **`Add file`（添加文件）** → **`Upload files`（上传文件）**。

### 4.3 拖拽上传

**方法一：直接拖拽（推荐）**

1. 打开项目文件夹
2. **全选所有文件和文件夹**（按 `Ctrl + A`）
3. 直接拖到网页中间的虚线框里

**方法二：点链接选择**

点页面上的 **`choose your files`（选择你的文件）**。

> ⚠️ **新手最常犯的错**：
> 只拖了根目录的几个文件，**漏掉了 `lib\`、`config\`、`docs\`、`tests\` 这些子文件夹**。
> 必须把这些**文件夹**也一起拖进去，否则别人下载后程序无法运行。

### 4.4 填写提交说明

页面下方有两个输入框：

| 输入框 | 填什么 |
|---|---|
| **Commit message**（提交说明） | `首次提交：校园网自动登录工具` 或 `Initial commit` |
| **Extended description**（详细描述） | 留空即可 |

### 4.5 提交

点击绿色的 **`Commit changes`（提交更改）** 按钮，等待几秒。

成功后会自动回到仓库首页，应该能看到所有文件和文件夹。

### 4.6 检查有没有漏传

**逐个点开每个文件夹确认：**

| 文件夹 | 应该看到 |
|---|---|
| `config\` | 只有 1 个文件：`config.example.json` |
| `lib\` | 6 个文件（main.ps1 等） |
| `docs\` | 2 个文件（使用说明.md、github-publish.md） |
| `tests\` | 4 个文件 |

**再次确认这些"不应该出现"的没出现：**

- ❌ 没有 `config.json`
- ❌ 没有 `data\` 文件夹

> **如果漏传了文件夹**，见 [第八阶段 8.2](#82-如何补充漏传的文件)。

## 第五阶段：完善仓库主页

### 5.1 确认 README 正常显示

回到仓库首页，往下滚动，
应该能看到 README 的内容被**排版好**显示出来（有标题、表格、目录）。

**如果显示的是一堆纯文本代码**，说明文件名不对。
必须是 `README.md`（全大写 `README`），不能是 `readme.md` 或 `README.txt`。

### 5.2 添加仓库简介和标签

在仓库首页**右侧**，找到 **`About`（关于）** 区域，点击旁边的**齿轮图标 ⚙️**：

| 填写项 | 填什么 | 示例 |
|---|---|---|
| **Description**（描述） | 一句话介绍 | `校园网 Portal 自动登录工具，零依赖、开箱即用` |
| **Website**（网站） | 留空 | 没有就不填 |
| **Topics**（标签） | 添加搜索标签 | `python` 可以不加；建议加：`campus-network`、`portal`、`autologin`、`windows`、`powershell` |

**Topics 的作用**：让其他人在 GitHub 上搜索时更容易找到你的项目。

填完点击 **`Save changes`（保存更改）**。

### 5.3 确认协议被识别

仓库首页右侧应该显示 **`MIT license`**。

**如果没有显示**，检查 `LICENSE` 文件：

- 文件名必须是 `LICENSE`（没有扩展名）
- 开头要有 `MIT License` 字样

## 第六阶段：发布第一个 Release

Release（发行版）的作用是：把某个版本"拍照存档"，别人可以直接下载。

### 6.1 进入创建页面

在仓库首页**右侧栏**，点击 **`Releases`（发行版）** → **`Create a new release`（创建新发行版）**。

或者直接访问：`https://github.com/你的用户名/你的仓库名/releases/new`

### 6.2 填写版本信息

| 填写项 | 填什么 | 说明 |
|---|---|---|
| **Choose a tag**（选择标签） | 输入 `v1.0.0`，然后点击出现的 **`Create new tag`** | 版本号 |
| **Target**（目标分支） | `main` | 保持默认不动 |
| **Release title**（发行版标题） | `v1.0.0 首个版本` | |
| **Describe this release**（更新说明） | 见下方示例 | |

**版本号怎么定：**

| 版本号 | 什么时候用 |
|---|---|
| `v1.0.0` | 第一个正式可用的版本 |
| `v1.0.1` | 修了小问题 |
| `v1.1.0` | 加了新功能 |
| `v2.0.0` | 有不兼容的大改动 |

**更新说明可以直接复制下面这段修改：**

```markdown
## 功能

- 校园网 Portal 自动登录，开机后自动完成认证
- 断线自动重连，持续保活
- 一条命令配置开机自启，无需管理员权限
- 后台静默运行，不弹窗打扰
- 账号信息全部外置到配置文件，代码中不含隐私信息
- 完全零依赖：不需要安装 Python、Node.js 或任何运行库

## 使用方法

1. 下载本项目（点 Code → Download ZIP）
2. 双击 `setup.bat`，按提示填写你的学号、密码、门户地址
3. 双击 `status.bat`，选 3 测试能否登录
4. 双击 `install.bat` 配置开机自启

详细说明见 [README](README.md)。

## 系统要求

- Windows 10 1709 或更高 / Windows 11
- 普通用户权限即可，不需要管理员

## 已知限制

- 目前仅适配 raas 门户系统
- Windows 7 / 8 可能无法运行
```

### 6.3 附加文件（可选）

如果你想把整个项目打包成 ZIP 一起提供下载，
可以把它拖到 **`Attach binaries`（附加文件）** 区域。

> ⚠️ **注意**：打包的 ZIP 里**绝对不能**包含 `config.json`。

其实**不附加也没关系**——GitHub 会自动为每个版本生成源码压缩包。

### 6.4 发布

点击 **`Publish release`（发布发行版）** 按钮。

## 第七阶段：验证发布成功

按下面的清单逐项确认：

| 序号 | 检查项 | 怎么查 | 期望结果 |
|---|---|---|---|
| 1 | 仓库能公开访问 | 用**无痕窗口**打开仓库链接 | 能看到完整内容 |
| 2 | 文件齐全 | 逐个点开文件夹 | 与本地一致，没有遗漏 |
| 3 | README 正常排版 | 看仓库首页 | 有标题、表格、目录 |
| 4 | 协议显示正确 | 看右侧栏 | 显示 `MIT license` |
| 5 | Release 存在 | 点右侧 `Releases` | 能看到 `v1.0.0` |
| 6 | **无隐私泄露** | 见下面 7.1 | 搜不到任何真实信息 |

### 7.1 隐私二次检查（必做）

**这是最后一道防线，务必执行。**

1. 在仓库页面顶部的搜索框里，输入你的**学号**，按回车
   → **应该搜不到**

2. 搜索你的**密码**
   → **应该完全搜不到**

3. 点开 `config\` 文件夹
   → **应该只有** `config.example.json` 一个文件

4. 看仓库**根目录的文件列表**
   → **应该没有** `data` 文件夹

5. 用**无痕窗口**打开仓库，确认陌生人看不到任何隐私内容

> **任何一项不通过**：立刻按 [8.4](#84-如何删除已上传的敏感文件) 处理。

## 第八阶段：发布后的日常操作

### 8.1 如何更新代码

**网页端修改（简单）：**

1. 点进要修改的文件（比如 `README.md`）
2. 点右上角的**铅笔图标 ✏️**（鼠标悬停会显示 `Edit this file`）
3. 修改内容
4. 滚到页面底部，填写提交说明，点 **`Commit changes`**

**新增文件：**

点 **`Add file`** → **`Create new file`（新建文件）** 或 **`Upload files`（上传文件）**。

### 8.2 如何补充漏传的文件

1. 点 **`Add file`** → **`Upload files`**
2. 把漏掉的文件或文件夹拖进去
3. 点 **`Commit changes`**

GitHub 会自动合并到现有目录结构，**不会覆盖其他文件**。

### 8.3 如何修改仓库介绍

仓库首页右侧 `About` 区域 → 点**齿轮图标 ⚙️** → 修改描述或标签 → 点 **`Save changes`**。

### 8.4 如何删除已上传的敏感文件

> ⚠️ **如果泄露的是密码，第一件事是去改密码，而不是先删文件。**

**删除步骤：**

1. 点进要删除的文件
2. 点右上角的**垃圾桶图标 🗑️**（鼠标悬停会显示 `Delete this file`）
3. 填写提交说明（如 `删除敏感文件`）
4. 点 **`Commit changes`**

**还要注意：**

- 文件虽然从最新版本删掉了，但**历史记录里可能还能找到**
- 稳妥做法：删除仓库重建，或联系 GitHub 官方支持清除历史

**最实际的建议**：一旦密码泄露，**立刻更换密码**，
这比纠结怎么删历史记录重要得多。

### 8.5 如何发布新版本

1. 先把代码改动提交（`Commit changes`）
2. 进入 `Releases` → `Create a new release`
3. 填**新的**版本号（如 `v1.0.1`）
4. 写更新说明
5. 点 `Publish release`

### 8.6 别人提了问题怎么办

仓库页面上方点击 **`Issues`（问题）** 标签，能看到所有反馈。

- 点进某条可以回复
- 修完后可以回复「已在 v1.0.1 修复」并关闭该问题

## 备选方案：用 Git 命令行上传

> **适合有一定基础的同学。**
> 只是想完成首次发布的话，**上面的网页端方案完全够用**。

### 为什么用命令行

- 能保留完整的修改历史
- 后续更新更方便（一条命令就能推送）

### 步骤（每条命令都附中文说明）

#### 第 1 步：安装并配置 Git

先从 **https://git-scm.com/download/win** 下载安装 Git。

然后打开命令提示符（按 `Win + R`，输入 `cmd` 回车），依次执行：

```bash
# 检查 Git 是否安装成功，会显示版本号
git --version

# 设置你的名字（会显示在提交记录里，改成你的 GitHub 用户名）
git config --global user.name "你的GitHub用户名"

# 设置你的邮箱（改成你注册 GitHub 用的邮箱）
git config --global user.email "你的邮箱"
```

#### 第 2 步：初始化仓库

```bash
# 进入你的项目目录（把路径改成你自己的）
cd /d D:\campus-autologin

# 把这个文件夹变成 Git 仓库
git init

# 把默认分支名改成 main（GitHub 的默认分支名）
git branch -M main
```

#### 第 3 步：检查将要提交的内容（关键一步）

```bash
# 查看有哪些文件会被提交
git status
```

**仔细检查列表里有没有 `config/config.json` 或 `data/`。**

**如果有，先停下来排查**，说明 `.gitignore` 没生效。

#### 第 4 步：添加并提交

```bash
# 把所有文件加入待提交区（.gitignore 里的文件会被自动跳过）
git add .

# 生成一次提交记录
git commit -m "首次提交"
```

#### 第 5 步：关联远程仓库

先在 GitHub 上创建一个**空仓库**（同第三阶段，三个选项都不勾）。

```bash
# 把本地仓库和 GitHub 上的仓库关联起来（换成你的仓库地址）
git remote add origin https://github.com/你的用户名/campus-autologin.git
```

#### 第 6 步：推送到 GitHub

```bash
# 把本地代码推送到 GitHub
git push -u origin main
```

首次推送会**弹出浏览器窗口要求登录 GitHub**，
按提示授权即可——**这是 GitHub 官方流程，密码不会经过第三方**。

> **提示**：如果你开启了两步验证，需要用 **Personal Access Token（个人访问令牌）** 代替密码。
> 获取路径：GitHub → `Settings` → `Developer settings` →
> `Personal access tokens` → `Tokens (classic)` → `Generate new token`。
> **令牌只显示一次，务必先复制保存好。**

#### 第 7 步：以后如何更新

```bash
# 把所有改动加入待提交区
git add .

# 生成提交记录（把说明改成你这次做了什么）
git commit -m "更新说明"

# 推送到 GitHub
git push
```

### 命令行常见问题

| 报错信息 | 原因 | 解决办法 |
|---|---|---|
| `remote origin already exists` | 已经关联过远程仓库 | 执行 `git remote set-url origin 新地址` |
| `failed to push some refs` | 远程有本地没有的提交 | 先执行 `git pull --rebase origin main` 再推送 |
| `Permission denied` | 认证失败 | 检查令牌是否过期，重新生成 |
| 推送后看不到 `config.json` | **这是正常的！** | 它被 `.gitignore` 忽略了，这正是我们想要的效果 |

## 新手避坑总表

| 序号 | 坑 | 后果 | 怎么避免 |
|---|---|---|---|
| 1 | 上传了填好的 `config.json` | **账号密码公开泄露** | 发布前跑 `check-privacy.bat` |
| 2 | 上传了 `data\` 目录 | 泄露日志和网络信息 | `.gitignore` 已屏蔽，上传前肉眼确认 |
| 3 | 建仓库时勾了「Add a README」 | 上传自己的 README 时报已存在 | **三个选项都不勾** |
| 4 | 建仓库时选了协议 | 上传自己的 LICENSE 时报已存在 | **三个选项都不勾** |
| 5 | 只拖了根目录文件 | 程序缺少 `lib\` 无法运行 | **连文件夹一起拖** |
| 6 | 仓库名用中文 | 分享链接容易乱码 | 用英文短横线命名 |
| 7 | README 文件名写错 | 主页不显示介绍 | 必须是 `README.md` |
| 8 | 把密码或令牌告诉别人 | 账号被盗 | **任何人都不要给** |
| 9 | 泄露后只删文件不改密码 | 密码已被人拿到 | **先改密码，再删文件** |
| 10 | 仓库选成 Private 却以为开源了 | 别人看不到 | 想开源就选 **Public** |
| 11 | 看不到 `.gitignore` 文件 | 以为文件不存在 | 资源管理器里开启「显示隐藏的项目」 |

## 常见问题

<details>
<summary><b>上传失败 / 一直转圈</b></summary>

**原因**：文件太多、网络不稳，或单个文件太大。

**解决办法**：

1. 刷新页面重新上传
2. 分批次上传：先传根目录文件，再逐个传子文件夹
3. 检查是否有超大文件（GitHub 单个文件上限 100 MB）
4. 换个网络环境（比如用手机热点）再试
</details>

<details>
<summary><b>提示「file already exists」（文件已存在）</b></summary>

**原因**：创建仓库时勾选了「Add a README file」或选了协议，
GitHub 已经帮你生成了同名文件。

**解决办法**：

1. 先把自己要上传的 README 改名为 `README-new.md` 上传
2. 然后删除 GitHub 上原有的 `README.md`
3. 再把 `README-new.md` 改名为 `README.md`

或者干脆**删掉仓库重建**，这次三个选项都不勾。
</details>

<details>
<summary><b>README 显示成一堆纯文本，没有排版</b></summary>

**原因**：文件名不对，或扩展名不是 `.md`。

**解决办法**：确认文件名是 **`README.md`**：

- 全大写 `README`
- 扩展名是 `.md`（不是 `.txt`）
- 需要在资源管理器里开启「文件扩展名」才能看准
</details>

<details>
<summary><b>上传后发现漏了某个文件夹</b></summary>

**解决办法**：`Add file` → `Upload files` → 拖入漏掉的文件夹 → `Commit changes`。

GitHub 会合并，不会覆盖其他内容。
</details>

<details>
<summary><b>开源协议该选哪个</b></summary>

| 协议 | 特点 | 适合场景 |
|---|---|---|
| **MIT** | 最宽松，别人可随意使用修改 | ✅ **本项目用这个**，工具类首选 |
| Apache-2.0 | 同样宽松，额外含专利授权条款 | 企业项目 |
| GPL-3.0 | 传染性：用了你的代码，衍生作品也必须开源 | 希望强制开源时 |

**新手建议直接用 MIT**，简单明了。
</details>

<details>
<summary><b>不小心泄露了密码怎么办</b></summary>

**按这个顺序做，顺序不能反：**

1. **立刻修改密码**（最重要，先止损）
2. 删除仓库里的敏感文件
3. 如果仓库刚创建不久，考虑直接删除仓库重建
4. 如果密码在多处复用，把其他地方的也换掉

> GitHub 上的公开内容会被爬虫抓取，
> 所以**改密码永远比删文件更优先**。
</details>

<details>
<summary><b>别人能看到我的邮箱吗</b></summary>

GitHub 默认会用你的邮箱生成提交记录。想隐藏：

`Settings` → `Emails` → 勾选
**`Keep my email addresses private`**（保持我的邮箱私密）
和 **`Block command line pushes that expose my email`**（阻止暴露邮箱的命令行推送）。
</details>

<details>
<summary><b>描述和 README 可以用中文吗</b></summary>

**完全可以。**

- 仓库**名称**建议用英文（链接更友好）
- 仓库**描述**、**README 内容**用中文没问题，方便国内用户阅读
</details>

<details>
<summary><b>网页端和命令行方案该选哪个</b></summary>

| 对比项 | 网页端 | 命令行 |
|---|---|---|
| 需要装软件 | ❌ 不需要 | ✅ 需要装 Git |
| 上手难度 | 简单 | 稍难 |
| 适合场景 | **一次性发布** | 需要频繁更新 |
| 保留修改历史 | 较弱 | 完整 |

**新手建议**：先用网页端完成首次发布，以后熟悉了再学命令行。
</details>
